2026 年 10 月 15 日の実機検証：ゲームを 1.06（Steam Build `25953419`）にアップデートしたところ、ゲーム本体は起動するものの、DiceMaster やセーブスロット拡張（Save Slot Expander）が反映されなくなりました。確認した結果、ゲーム本体が 32bit から 64bit へ移行した一方、Mod フレームワークを注入する Doorstop（エントリツール）が従来の 32bit 版のまま残っていたことが原因と判明しました。

今回、Doorstop `4.4.0` の Windows x64 版 `winhttp.dll` に差し替え、従来の BepInEx `6.0.0-be.785`、DiceMaster `1.0.0`、セーブスロット拡張 `1.2.0` を維持したところ、プラグインの読み込みが復旧しました。セーブスロット拡張はプレイヤーによる動作確認済み、DiceMaster の選択肢補正表示はスクリーンショットによる表示確認済みです。**日本語化 Mod の 1.06 環境における互換性は別途検証が必要です。**

## 本現象に該当するか確認する

本事例が該当するのは、「ゲーム更新後にメインメニューまでは入れるが、これまで使えていた Mod が一斉に動かなくなった」場合です。旧ガイドの手順で 32bit 版 Doorstop を導入していた場合は、まずゲーム本体とエントリ DLL のビット数を確認してください。

| 確認対象ファイル | 今回の更新後の実測結果 | 意味 |
| --- | --- | --- |
| `Mortal.exe`、`UnityPlayer.dll` | PE32+ / x86-64 | ゲーム本体が 64bit に更新された |
| 既存の `winhttp.dll` | PE32 / x86 | 旧 32bit 版 Doorstop のままのため差し替えが必要 |
| BepInEx、DiceMaster、セーブスロット拡張 | マネージドアセンブリ（.NET DLL）、`Requires32Bit` フラグなし | 今回維持したまま 64bit ゲーム内で正常に読み込み完了。ゲーム側のアーキテクチャ変更を理由にマネージドコアまでむやみに差し替えないこと |

Doorstop は、ゲームディレクトリ内の `winhttp.dll` を介して起動時に BepInEx（Unity Mod フレームワーク）を読み込み、BepInEx が各 Mod を読み込みます。ネイティブ DLL は `Mortal.exe` とビット数を一致させる必要がありますが、マネージドプラグイン（C# で書かれた Mod アセンブリ）はプラグイン自体の互換性と実機能の検証によって判断すべきであり、一律に差し替える必要はありません。

## 修復手順

### 1. ゲームを終了してバックアップを作成

ゲーム内で通常どおりセーブして終了し、ラッパー（Wrapper：macOS 上の Wine 実行環境）内の Windows 版 Steam も終了します。Wine セッションを終了させる必要がある場合は、本ゲームのラッパーのみを対象としてください。

ゲームディレクトリ内の `winhttp.dll`、`doorstop_config.ini`、および `BepInEx` ディレクトリ全体をバックアップし、ファイルバージョンと SHA-256 ハッシュ値を記録します。ランタイム構成も同時に更新する場合は、ラッパー全体のバックアップを別途作成してください。今回の実測ではラッパー全体のバックアップを使用しました。

### 2. ゲーム本体と DLL のビット数を確認

macOS のターミナルで以下の 2 つの読み取り専用コマンドを実行します。`/path/to/LegendOfMortal` は各自のゲームディレクトリの絶対パスに置き換えてください。

```bash
file "/path/to/LegendOfMortal/Mortal.exe"
file "/path/to/LegendOfMortal/winhttp.dll"
```

修復前の実測では、ゲーム本体は `PE32+` / `x86-64`（64bit）、`winhttp.dll` は `PE32` / `Intel 80386`（32bit）と表示されました。このビット数の不一致が、今回エントリ注入が機能しなかった原因です。

### 3. Windows x64 版 Doorstop に差し替え

[UnityDoorstop 4.4.0 公式リリースページ](https://github.com/NeighTools/UnityDoorstop/releases/tag/v4.4.0) から Windows 版を入手し、解凍後に x64 版 `winhttp.dll` を確認のうえ、ゲームルートディレクトリの同名ファイルと置き換えます。Wine 経由で実行するゲームには Windows 版 DLL を使用します。

今回は既存の `doorstop_config.ini`、完全な corlibs（Unity コア依存ライブラリ）、および BepInEx マネージドコアをそのまま維持しました。既存の BepInEx、DiceMaster、セーブスロット拡張には 32bit 強制フラグが設定されておらず、今回の 64bit 起動で正常に読み込まれました。ゲームのアーキテクチャが変わったからといって、マネージドコアまでむやみに差し替えないでください。他バージョンのプラグインは個別に確認が必要です。

ラッパーの `winecfg` を開き、**Applications** タブで `Mortal.exe` を選択したうえで、**Libraries** タブで本ゲーム専用のオーバーライド設定を確認します：

```text
winhttp = native,builtin
```

この設定により、Wine はゲームディレクトリ内の Doorstop ネイティブファイルを優先して読み込みます。ゲーム更新後も Unity エンジンのバージョンは `2020.3.49f1` のままであり、今回は引き続き同バージョンに適合する corlibs を使用しています。ゲーム更新時は Unity バージョンも都度確認してください。

### 4. 今回の起動ログで読み込みを確認

ゲーム起動後、`BepInEx/LogOutput.log` の更新日時が今回のゲーム起動時刻より新しいことを確認します。旧ログの残留は今回の切り分けでも誤認の原因となりました（ログが 16:12 で停止している一方、ゲームは 16:14 に再起動していた事例など）。

修復後の 16:25 の起動ログには以下の内容が記録されました：

```text
Process bitness: 64-bit (x64)
Chainloader initialized
Loading [DiceMaster 1.0.0]
Loading [LOM Save Slot Expander 1.2.0]
Chainloader startup complete
```

`Process bitness: 64-bit (x64)` により現在のプロセスが 64bit であること、`Chainloader initialized` によりフレームワークが起動したこと、各 `Loading [...]` 項目により各プラグインがロード工程に入ったことが確認できます。最後にゲーム内で実際の機能を確認します。

## 今回検証できた範囲

### 日本語化 Mod v2.5 について

同日公開された日本語化 Mod v2.5 は、パッケージの静的解析を完了しました。本パッケージには 64bit 版 Doorstop（バージョン表記 `4.3.0`）、バージョン別に管理されたランタイムと翻訳データ、および新しいレイアウト調整が含まれています。ただし同梱の BepInEx コアは `be.692` のため、一括で上書き導入すると、本環境で動作確認済みの `be.785` が置き換わってしまいます。試す際は事前に現在の環境をバックアップし、フレームワークの初期化、新規プラグインの読み込み、日本語の表示状態を段階的に確認することをおすすめします。なお、本稿で紹介した Doorstop `4.4.0` による起動実績はローカル環境で独自に修復した結果であり、v2.5 の動作証拠ではありません。v2.5 自体の macOS 上での実機動作は引き続き未検証です。

### 確認済み項目と未検証項目

| 項目 | 条件と結果 | 証拠と信頼度 |
| --- | --- | --- |
| ゲーム本体および Mod フレームワーク起動 | Build `25953419`、x64 版 Doorstop、新規ログに 64bit および Chainloader 完了を記録 | 実行中プロセスモジュールおよび今回の起動ログ；高 |
| セーブスロット拡張 `1.2.0` | プレイヤーによるセーブスロット拡張機能の動作確認 | プレイヤーの実機操作確認；高（確認済み機能のみ） |
| DiceMaster `1.0.0` 選択肢情報 | 選択肢の補正値表示が復旧 | プレイヤーのゲーム内スクリーンショット；高（表示のみ；数値の正確性および新ストーリー解析は未検証） |
| DiceMaster メニュー | ローカル環境のショートカットキーを `F10` に設定（手動設定キーであり共通デフォルトではありません）、内蔵キーボードは `Fn + F10` | ローカルキー設定確認済み；メニュー操作の動作は未検証 |
| 日本語化 Mod | 1.06 環境でのテスト未実施 | 未検証 |
| フォント表示、ウィンドウ切り替え、スリープ復帰、長時間プレイ | 今回は起動、グラフィック、オーディオの初期化確認のみ実施 | 今後の実プレイ検証待ち；旧版での検証結果は過去のガイドに維持 |

DiceMaster の検証にあたっては、効果が明確な新ストーリーの選択肢を選び、選択前後の実際のステータス変化を比較することや、新規ダイスイベントおよび分岐の動作を確認することが推奨されます。「表示が出る」「数値が正確である」「ダイス判定制御が効く」はそれぞれ個別に確認すべき項目です。今回の検証では、新規ストーリーの解析、数値の正確性、ダイス制御、特殊リザルト判定、および F10 メニュー操作の完全な互換性は未検証です。

## ロールバック（復元）が必要な場合

復元が必要な場合は、まずゲーム、Windows 版 Steam、および該当ラッパーの Wine セッションを正常終了してから、バックアップを段階的に戻します。Doorstop のみを差し替えた場合は以前の `winhttp.dll` のみを復元し、ランタイム構成を更新した場合は一式バックアップからその層を復元します。

ラッパー全体のバックアップには、バックアップ作成時点のセーブデータも含まれます。バックアップ作成後にゲームをプレイして新たな進行状況がある場合は、ラッパー全体を復元する前に必ず新しいセーブデータを個別に退避し、上書きによる進行喪失を防ぐとともに、セーブデータとゲームバージョンの互換性を確認してください。BepInEx マネージドコアを復元する際は、ビルド一式単位で扱ってください。
