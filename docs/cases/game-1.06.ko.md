# 《활협전》 1.06 업데이트 후 모드 미작동: 64비트 진입점 먼저 확인하기

[한국어 가이드로 돌아가기](../guide.ko.md) · [简体中文](game-1.06.zhs.md) · [繁體中文](game-1.06.zht.md) · [日本語](game-1.06.ja.md)

2026년 10월 15일 실측 검증: 게임 1.06 및 Steam Build `25953419`로 업데이트한 후, 게임은 정상 실행되지만 DiceMaster와 세이브 슬롯 확장(Save Slot Expander) 모드가 적용되지 않는 현상이 발생했습니다. 확인 결과, 게임 실행 파일이 32비트에서 64비트로 전환된 반면, 모드 프레임워크를 주입하는 Doorstop(진입 도구)이 여전히 구버전 32비트로 남아 있던 것이 원인이었습니다.

이번에 Doorstop `4.4.0`의 Windows x64 버전 `winhttp.dll`로 교체하고, 기존 BepInEx `6.0.0-be.785`, DiceMaster `1.0.0`, 세이브 슬롯 확장 `1.2.0`을 유지한 결과 플러그인 로드가 정상 복구되었습니다. 세이브 슬롯 확장은 플레이어를 통해 동작이 확인되었으며, DiceMaster의 선택지 보정 정보 표시는 스크린샷을 통해 정상 표시가 확인되었습니다. 일본어 모드 v2.5의 Mac 설치와 검증은 [일본어 페이지](japanese-mod-v2.5.ja.md)에 정리되어 있습니다.

## 해당 문제에 해당하는지 먼저 확인하기

본 가이드의 사례는 게임 업데이트 후 메인 메뉴까지 진입할 수 있으나, 기존에 사용하던 모드가 일제히 작동하지 않는 상황에 해당합니다. 이전 가이드에 따라 32비트 Doorstop을 설치한 적이 있다면, 게임 본체와 진입 DLL의 비트 수를 우선 확인해야 합니다.

| 확인할 파일 | 이번 업데이트 후 실제 결과 | 의미 |
| --- | --- | --- |
| `Mortal.exe`, `UnityPlayer.dll` | PE32+ / x86-64 | 게임 본체가 64비트로 변경됨 |
| 기존 `winhttp.dll` | PE32 / x86 | 여전히 구형 32비트 Doorstop 진입점이므로 교체 필요 |
| BepInEx, DiceMaster, 세이브 슬롯 확장 | 관리 어셈블리(.NET DLL), `Requires32Bit` 플래그 없음 | 이번에 유지한 상태로 64비트 게임 내에서 정상 로드됨. 게임 아키텍처가 바뀌었다고 해서 관리 코어까지 무분별하게 교체하지 말 것 |

Doorstop은 게임 디렉터리 내의 `winhttp.dll`을 통해 게임 실행 시 BepInEx(Unity 모드 프레임워크)를 로드하고, BepInEx가 각 모드를 로드합니다. 네이티브 DLL은 `Mortal.exe`의 프로세스 비트 수와 정확히 일치해야 하지만, 관리 플러그인(C#으로 작성된 모드 어셈블리)은 플러그인 자체의 호환성과 실제 기능 검증을 통해 판단해야 하며 무조건 교체할 필요는 없습니다.

## 복구 절차

### 1. 게임 종료 및 백업

게임 내에서 정상적으로 저장 후 종료하고, 래퍼(Wrapper: macOS 상의 Wine 실행 환경) 내의 Windows 버전 Steam도 종료합니다. Wine 세션을 강제 종료해야 하는 경우 해당 게임이 위치한 래퍼만 대상으로 지정합니다.

게임 디렉터리 내의 `winhttp.dll`, `doorstop_config.ini`, 그리고 `BepInEx` 전체 디렉터리를 백업하고 파일 버전 및 SHA-256 해시를 기록합니다. 런타임 구성 요소도 함께 업그레이드할 경우 래퍼 전체를 별도로 백업합니다. 이번 실측에서는 전체 래퍼 백업을 사용했습니다.

### 2. 게임 본체 및 DLL 비트 수 확인

macOS 터미널에서 다음 두 개의 읽기 전용 명령을 실행합니다. `/path/to/LegendOfMortal` 부분은 본인 게임 디렉터리의 실제 절대 경로로 변경하십시오.

```bash
file "/path/to/LegendOfMortal/Mortal.exe"
file "/path/to/LegendOfMortal/winhttp.dll"
```

이번 복구 작업 전 실측 시, 게임 본체는 `PE32+` / `x86-64`(64비트)로 표시되었으나 `winhttp.dll`은 `PE32` / `Intel 80386`(32비트)으로 표시되었습니다. 이 비트 수 불일치가 진입점 주입 실패의 원인이었습니다.

### 3. Windows x64 버전 Doorstop으로 교체

[UnityDoorstop 4.4.0 공식 릴리스 페이지](https://github.com/NeighTools/UnityDoorstop/releases/tag/v4.4.0)에서 Windows 버전을 다운로드하고, 압축 해제 후 x64 버전 `winhttp.dll`을 확인한 뒤 게임 루트 디렉터리의 동일 파일과 교체합니다. Wine을 통해 실행되는 게임에는 Windows용 DLL을 사용해야 합니다.

이번 작업에서는 기존 `doorstop_config.ini`, 완전한 corlibs(Unity 핵심 종속 라이브러리), BepInEx 관리 코어를 그대로 유지했습니다. 기존 BepInEx, DiceMaster, 세이브 슬롯 확장은 32비트 강제 플래그가 설정되어 있지 않아 이번 64비트 부팅에서 모두 성공적으로 로드되었습니다. 게임 아키텍처가 변경되었다고 해서 관리 코어까지 무분별하게 교체하지 마십시오. 다른 버전의 플러그인은 개별적으로 확인해야 합니다.

래퍼의 `winecfg`를 실행하여 **Applications** 탭에서 `Mortal.exe`를 선택한 후, **Libraries** 탭에서 해당 게임 전용 설정을 확인합니다:

```text
winhttp = native,builtin
```

이 설정은 Wine이 게임 디렉터리 내의 Doorstop 네이티브 파일을 우선 사용하도록 지정합니다. 게임 업데이트 후에도 Unity 엔진 버전은 `2020.3.49f1`로 유지되었으므로, 이번 작업에서도 해당 버전에 맞는 corlibs를 계속 사용합니다. 게임 업데이트 시 Unity 버전도 항상 재확인해야 합니다.

### 4. 이번 부팅 로그로 모드 로드 확인

게임을 실행한 후, `BepInEx/LogOutput.log` 파일의 수정 시각이 이번 게임 실행 시각보다 최신인지 확인합니다. 이전 로그의 잔류는 이번 문제 분석 과정에서도 오판을 초래한 바 있습니다(로그는 16:12에 멈춰 있었으나 게임은 16:14에 재실행된 사례 등).

복구 후 16:25 실행 로그에는 다음 내용이 포함되었습니다:

```text
Process bitness: 64-bit (x64)
Chainloader initialized
Loading [DiceMaster 1.0.0]
Loading [LOM Save Slot Expander 1.2.0]
Chainloader startup complete
```

`Process bitness: 64-bit (x64)` 항목은 현재 프로세스가 64비트임을 확인하며, `Chainloader initialized`는 프레임워크가 정상 시작되었음을 나타냅니다. 각 `Loading [...]` 항목은 해당 플러그인이 로드 절차에 진입했음을 증명합니다. 마지막으로 게임 내에서 실제 필요 기능을 직접 확인해야 합니다.

아래는 본 기기에서 최종 적용한 구성 조합이며 검증 일자는 2026년 10월 15일입니다. 진입점 복구와 런타임 업그레이드를 별도로 기록하여 각 변경의 구체적인 영향을 명확히 파악할 수 있도록 했습니다.

| 구성 요소 | 이번 최종 구성 |

| Unity | `2020.3.49f1` |
| Doorstop | `4.4.0` Windows x64 |
| BepInEx | `6.0.0-be.785` 관리 코어 유지 |

Steam 로그인, 게임 실행, D3D11 feature level 11.1, 오디오 초기화 및 씬 로드가 모두 정상 통과되었습니다. Wine 11.0 revision 1은 본 기기의 기존 환경 및 신규 빈 환경 모두에서 `wineboot` 초기화 단계에서 멈추는 현상이 발생하여 원인 조사 중(본 기기 한정 미해결 문제)입니다. 이에 따라 검증 완료된 Wine 10.0 revision 8을 최종 채택했습니다. 본 관찰 결과는 이번 테스트 환경에만 적용됩니다.

## 롤백(복원)이 필요한 경우

복원이 필요한 경우 게임, Windows 버전 Steam, 해당 래퍼의 Wine 세션을 정상 종료한 후 단계별로 백업을 복원하십시오. 예를 들어 Doorstop만 교체한 경우 이전 `winhttp.dll`만 복원하고, 런타임 구성 요소를 업그레이드한 경우 해당 세트 백업에서 해당 레이어를 복원합니다.

래퍼 전체 백업에는 백업 시점의 게임 세이브 파일도 포함됩니다. 백업 이후 게임을 플레이하여 새로운 진행 상황이 발생한 경우, 래퍼 전체를 복원하기 전에 반드시 새 세이브 파일을 별도로 백업하여 진행 데이터가 이전 세이브로 덮어씌워지지 않도록 주의하고 세이브와 게임 버전 간 호환성을 확인하십시오. BepInEx 관리 코어를 복원할 때는 완전한 빌드 단위로 일괄 처리하십시오.
